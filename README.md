# Burmalda Uptime Bot

Telegram-бот следит за нодами 3x-ui двумя способами:

1. Статус узла берётся из `/panel/api/nodes/list` главной панели.
2. Для онлайн-узлов check-host.net отправляет HTTP-запросы из России и из
   других стран. HTTP-ответ, включая 404, подтверждает доступность адреса.
   Недоступность из РФ требует отказа как минимум двух российских проб,
   успешной зарубежной пробы и повторного подтверждения спустя
   `CONFIRMATION_DELAY_SECONDS` (по умолчанию 7 секунд).

## Запуск

Скопируйте `.env.template` в `.env`, заполните значения и запустите:

```console
docker compose up -d --build
```

`CHAT_ID` — чат/канал для статуса и уведомлений. `MESSAGE_ID` — ID уже
существующего сообщения в этом чате, которое бот должен редактировать.

При любом сообщении боту в личном чате он отправляет сводку: время работы
процесса, текущее состояние и длительность состояния каждой локации, а также
последние десять подтверждённых сбоев с момента запуска.

## Структура

- `bot.py` — сборка приложения и запуск polling;
- `vpn_monitor/clients.py` — API панели и check-host;
- `vpn_monitor/probes.py` — статус панели и повторное подтверждение проверки из РФ;
- `vpn_monitor/state.py` — состояния, переходы и история инцидентов;
- `vpn_monitor/formatting.py` — сообщения Telegram;
- `vpn_monitor/handlers.py` — ответы в личном чате;
- `vpn_monitor/monitor.py` — основной цикл мониторинга;
- `vpn_monitor/node_history.py` — замеры онлайна и статусов узлов в SQLite;
- `vpn_monitor/reminders.py` — уведомления админам об истечении подписок;
- `vpn_monitor/payments.py` — журнал оплат и статистика выручки;
- `vpn_monitor/panel_api.py` — типизированный клиент API 3x-ui;
- `vpn_monitor/panel_models.py` — модели ответов 3x-ui;
- `vpn_monitor/admin/` — роутеры, кнопки, представления и графики админ-панели.

Сводка инцидентов в личке ведётся с момента запуска бота. Замеры для графиков
хранятся до 30 дней в `data/node-history.sqlite3` и переживают перезапуск.

## Админ-панель 3x-ui 3.11.0

Версия подтверждена через API на центральной панели и всех подключённых нодах.

Команда `/admin` открывает приватную inline-панель. Она работает только в личном
чате и только для Telegram ID из `ADMIN_IDS`. Значения указываются через
запятую:

```dotenv
ADMIN_IDS=123456789,987654321
```

Панель использует Bearer-токен из `API_KEY` и официальные endpoints 3x-ui:

- общая статистика пользователей и суммарный upload/download;
- список узлов с флагами, CPU, RAM, online-клиентами и состоянием Xray;
- график CPU/RAM и график онлайн-пользователей за последние 24 часа для каждой ноды;
- общий и отдельный графики аптайма по 30 календарным дням;
- серверная пагинация пользователей;
- поиск по email, Sub ID, UUID или полной subscription URL;
- статистика пользователя, квота, срок действия и последний online;
- кнопка Telegram для копирования subscription URL;
- изменение точного лимита трафика (`-1` — безлимит);
- установка даты окончания, прибавление/вычитание дней и бессрочный режим;
- просмотр и удаление отдельных HWID;
- создание подписки со случайным email на всех входящих, с лимитом 10 HWID,
  безлимитным трафиком и Flow `xtls-rprx-vision` на совместимых входящих;
- замена ссылки с переносом срока и попыткой переноса текущих счётчиков;
- напоминания об истечении подписки в ближайшие 24 часа для группы «СВОи, не трогать»;
- запись оплат и отчёты по выручке с графиком за 12 месяцев.

График онлайна использует `onlineCount` из 3x-ui. Для аптайма цвет дня
показывает худший подтверждённый статус за календарные сутки по МСК:
зелёный — доступно, жёлтый — недоступно из РФ, красный — офлайн,
серый — статус не подтверждён. Графики заполняются по мере накопления замеров.

При замене создаётся новый клиент с новыми ключами. Старый клиент удаляется
через 24 часа после создания новой ссылки либо после восстановления API, если
к этому времени панель недоступна. Обе подписки сохраняют исходный срок,
поэтому истечение срока может отключить их раньше. HWID регистрируются на
новой подписке заново. Трафик старого клиента за эти 24 часа не суммируется
с новым. Задания на удаление хранятся в SQLite в каталоге `data/`.

Для графика CPU/RAM бот сначала запрашивает шаг агрегации 360 секунд,
при необходимости перебирает остальные варианты и запоминает первый рабочий.

`PANEL_API_URL` обычно указывать не нужно: бот получает его из
`NODES_API_URL`, отбрасывая `/nodes/list`. При нестандартном адресе задайте его
явно, например `https://panel.example.com/panel/api`.

Ссылка подписки строится из `subURI` панели. Если он пуст, используются
`subDomain` (либо `webDomain`), `subPort`, `subPath` и настройки TLS. Для панели
за reverse proxy лучше явно заполнить `subURI`, чтобы кнопка копировала внешний,
а не внутренний адрес.

На сервере изменения доставляются через ветку `deploy`, которую GitHub Actions
обновляет после проверок коммита в `main`. Таймер
`vpn-monitor-bot-deploy.timer` проверяет ветку раз в минуту. Журнал доступен
через `journalctl -u vpn-monitor-bot-deploy.service`. Настройки и SQLite
остаются в серверном каталоге и исключены из Git.

Для локальной пересборки:

```console
docker compose up -d --build
```

Проверки качества:

```console
python -m black --check .
python -m flake8 .
python -m unittest discover -v
```
